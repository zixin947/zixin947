# 个人主页设计与维护

## 已确认的方向

2026-10-28：保留中文介绍，参考 rahul05ranjan 的个人主页组织方式，使用打字动画、徽章、双列项目卡片、技术图标、统计图与贡献蛇。用户已确认直接更新个人主页仓库。

主页面向希望了解项目和贡献的开发者。介绍以现有简介及公开仓库为依据；个人项目与上游贡献分开，Codex Atelier 明确保留原型状态。这里只展示公开资料，联系方式使用已有 GitHub Issues 入口。

## 决策

| 决策 | 取舍与原因 |
| --- | --- |
| Markdown + GitHub 支持的 HTML | 直接在个人主页渲染，不需要独立网站或客户端脚本。 |
| 双列项目卡片 | 参考页的核心布局；只放两个已有公开个人项目，避免填充未经核实的项目。 |
| 以中文为主，技术术语保留英文 | 延续原简介语言；打字图使用英文技术方向，保持短行。 |
| 自行生成仓库内统计 SVG | 相较直接依赖外部统计卡服务，可保留上一次成功的结果并明确统计范围。 |
| 每 6 小时刷新 | 满足个人主页更新频率，减少请求与维护成本。GitHub 定时任务可能延迟；长期不活跃的公开仓库可能需要重新启用。 |
| 贡献数据链接到实时查询 | 不在正文手动维护可能过时的 PR 数字。只统计公开的上游已合并 PR。 |
| 使用贡献蛇的亮色与深色版本 | 适配 GitHub 两种主题。图片生成失败时工作流失败，不覆盖已提交的旧资源。 |
| 不复制参考页的文案和成果 | 仅借鉴组织方式，技能与成果以自己的公开资料为依据。 |

## 数据与边界

- `scripts/update-profile.py` 使用 GitHub CLI 读取公开用户资料、公开仓库数、关注者、公开上游已合并 PR，以及 `dsh-compact` / `codex-atelier` 的语言字节数。
- 语言图按两个项目的字节数合计绘制，包含框架基础文件；不代表投入时间或掌握程度，也不包含贡献用 Fork。
- 卡片使用固定配色和转义后的文本，不嵌入脚本、凭据或私人数据。
- 贡献蛇使用 `Platane/snk`。Actions 使用仓库自带的 `GITHUB_TOKEN`，第三方 Actions 固定到完整 commit SHA。
- 工作流不由 PR 触发；失败时保留旧图，不提交半成品。打字图、徽章和技术图标依赖其第三方图片服务。
- 不需要访问量追踪；主页维护不需要新增个人访问令牌。

## 维护与回退

- 修改介绍：编辑 `README.md`。
- 修改统计范围：编辑脚本中的 `LANGUAGE_REPOS`。
- 手动刷新：在 Actions 中运行“更新主页图表”。本地也可在已登录 `gh` 后运行 `python3 scripts/update-profile.py`。
- 暂停自动更新：在 Actions 页面停用该工作流。
- 回退页面：对主页改版提交执行 `git revert`，然后推送到 `main`。

## 验证方式

检查 Markdown 的 GitHub 渲染、桌面与窄屏显示、图片加载、项目和贡献查询链接，以及首次 Actions 的运行结果。统计脚本运行和 `git diff --check` 是最低检查；无应用构建或业务测试。
